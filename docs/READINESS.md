# Readiness and acceptance

| State | Required evidence | Does not establish |
|---|---|---|
| Scaffold validated | Source fidelity, governance maps/bytes, helper positive/negative tests, private FIFOs, inactive receipt | Product behavior or activation |
| Activation ready | Current human authority, coherent remote/CI/merge-side-effect checks, panes/client configuration, source freshness, sole consumers | Milestone acceptance |
| Synthetic demo | Implemented end-to-end composition with controlled fake models/synthetic data, honest labels | Real model quality/hardware capacity |
| Text-core MVP | A01–A29/A32–A40 relevant scope, real qualified gateway/model/embedding/rerank or tested fallback, held-out retrieval/support, security/recovery/license evidence and ICA | Visual capability or production permission |
| Full visual MVP | Text core plus A30–A31 audited extraction/vision route, original visual citation and separate quality evidence, ICA | Human deployment approval |
| Controlled pilot | Applicable human DHA decisions, approved data/identity/hosts/exposure, realistic load/recovery and explicit pilot authorization | Broader production use |
| Production | Target-specific ICA, applicable human ACCEPTED dispositions, license/data/security/operations acceptance and explicit release/deploy authority | Unqualified hosts/models/data or future versions |

No percentage based on objectives completed. Report code completeness, evidence confidence,
unresolved uncertainties and technical/judgment debt separately. A provisional fallback needs
measured evidence and recorded rationale; it cannot quietly revise human-owned scope.
Final latency and concurrency targets follow baseline measurement and stated expected workload.
ICA classifies source requirements independently at exact merged revision; relevant changes and
closure remediation require reassessment. No scaffold self-review is an independent audit.
