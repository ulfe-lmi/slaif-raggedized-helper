# Agent roles and context discovery

The human assigned strategic role in codex-supervision/slaif-raggedized-helper and coding role
in codex-work/slaif-raggedized-helper. Runtime binds exact tmux panes, validated before wake.
Role comes from explicit instruction/trusted prompt, not cwd or environment alone. Reading
another role's law never grants its authority. Root router is deliberately small; coding reads
the dense constitution plus compact architecture/protocol/security/testing, active order and
relevant subtree contracts. Strategic law keeps full-source stewardship and ICA responsibilities.

Existing clients and their model/provider/profile/effort are preserved. Private optional homes
agent-homes/{strategic,coding} are empty setup destinations, not active credential stores. A
future client replacement must be explicitly configured; do not copy global auth/history or
silently select a model. New coding rounds use a fresh conversation in the current approved
CLI; strategic continuity is logical and reconstructs from durable evidence after restart.

Client qualification records installed version/help and an observed read-only startup/fresh
conversation check. Fake tmux tests prove argument/directory/role guards only, not actual client
instruction discovery, model behavior or complete request token cost. Missing qualification
remains PENDING in runtime. Setup shells are usable before authentication or activation.
