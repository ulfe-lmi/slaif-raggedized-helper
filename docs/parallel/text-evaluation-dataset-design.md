## API and trust

admit(dataset_bytes, *, deadline_ms=5000) returns a frozen Dataset containing immutable tuples of admitted Case/Requirement/GoldSpan values, canonical_bytes, namespace, split_policy_ref, dataset_id, split_id and the declared counts as direct fields. Dataset.cases and each Case.requirements, Case.acceptable_facts and Case.disallowed_claims are tuples; Case.scope is a frozen DeclaredScope with corpora/versions/labels tuples; Requirement.alternatives is a tuple of GoldSpan tuples. Exact built-in bytes input and int deadline1..30000 (bool refused). Capture original monotonic start before admission. Check time through bounded loops, after serialization/hashes/result construction and immediately before success. Deadline is cooperative and does not preempt JSON decoding.

Pure standard-library implementation: no Pydantic, NumPy, stores, provenance registry, model, worker, network, subprocess or file I/O imports. It admits declarations, not verified source or human authority. No mutable input objects or shared list/dict references survive in results. Default repr of Dataset and nested records must not expose questions, claims, refs or span hashes (dataclasses repr=False or equivalent). ALL ordinary failures, including decoder syntax/duplicate/Unicode/RecursionError/limit-hook errors, raise DatasetError("text evaluation dataset refused") from None. Default str/repr and traceback suppress the original context; this does not claim that __context__ is inaccessible to a trusted Python caller. Original non-Exception interruptions propagate with identity unchanged. No automatic printing or serialization to logs.

Fixed result markers: qualification=NOT_QUALIFIED, authorship_status=DECLARED_UNVERIFIED, rights_status=DECLARED_UNVERIFIED, split_status=STRUCTURAL_ONLY. Counts labelled human_declared never imply verified human authorship or held-out provenance. All four markers are direct Dataset read-only properties or frozen init=False constants; constructor arguments cannot select alternative qualification values. Nested records carry only their explicitly mapped data, not extra caller-controlled verification flags. Every nested record including DeclaredScope suppresses default field repr. No method promotes qualification from a caller string/ref. Real data/rights, semantic leakage review and qualified execution remain separate gates.

## Encoding and global bounds

Canonical ASCII JSON: json.dumps(sort_keys=True,ensure_ascii=True,separators=(",",":"),allow_nan=False).encode("ascii") must equal input exactly. Refuse duplicate object keys, floats/nonfinite constants, wrong exact types, missing/unknown keys and trailing bytes. Source text remains exact Unicode/UTF8; no case folding, NFC normalization, stripping or technical punctuation/version merging. Invalid Unicode/surrogates refuse.

Input1..16777216B, JSON nodes<=200000, nesting depth<=16, cases1..512. Global decoded text budget<=4000000 Unicode codepoints across ALL keys and string values in the parsed tree, counted once per occurrence, plus total gold atom occurrences<=4096 and total facts/disallowed-claim occurrences<=8192. Count tree nodes/depth/text before constructing retained records; bounded JSON input controls the initial decoder allocation, not a claim of a hard memory preemption. Record the traversal/work limit honestly. Integers use signed64 range[-9223372036854775808,9223372036854775807] before tighter field bounds. Provide a bounded json.loads parse_int hook: check optional minus, decimal digit count and lexical boundary BEFORE int conversion, then convert at most19 magnitude digits. Reject floats/constants and duplicate keys with decoder hooks. Canonical -0 still refuses by byte comparison. No arbitrary integer conversion or executable deserializer. Decode ASCII and catch ordinary decoder/recursion/Unicode failures as the fixed DatasetError; do not call that an allocation preemption.

Traversal convention: the root JSON value is one node at depth0. Each object key is one string node at parentdepth+1 and each object value is one node at parentdepth+1; each array member is one node at parentdepth+1. Containers and primitive values count, with no extra node for an object pair. Count every key/string occurrence even if decoder storage interns it. Validate UTF8 encoding of EVERY key and string value during traversal so escaped lone surrogates cannot survive. Check time after decode and throughout traversal.

Lexical order of strings means Python Unicode-codepoint lexicographic order without normalization/locale; identifiers are ASCII but scope/block strings may be Unicode. Integer tuple fields compare numerically. Alternative order is separately canonical ASCII BYTE order, as specified below.

Every array below must use the specified order; do not sort/deduplicate invalid input into validity. All input dicts have exactly the fields listed. Empty is allowed only where specified. Frozen output fields map EXACTLY to the input field names: Dataset.cases, Case.acceptable_facts, Case.disallowed_claims, Case.requirements, Requirement.requirement_id/grade/alternatives and GoldSpan fields as listed; scope maps to DeclaredScope with corpora/versions/labels. All other Case scalar/ref fields retain the same names and exact admitted values. Dataset has canonical_bytes, namespace, split_policy_ref, dataset_id, split_id, the seven direct count fields listed later and the four fixed markers. Frozen output tuples preserve admitted order. Hash identities do not prove rights/privacy or semantic correctness.

## Exact root and case schema

Root: schema integer1; kind="slaif-text-evaluation-dataset-v1"; namespace; split_policy_ref; cases.

namespace, case_id, family_id and requirement_id are printable ASCII identifiers matching [A-Za-z0-9][A-Za-z0-9._:-]{0,127}. split_policy_ref and the per-case authorship_ref, rights_ref, split_review_ref are nonempty UTF8 strings<=512 codepoints/2048 UTF8 bytes, with no control characters; require at least one non-whitespace character; opaque declared evidence locators only, never fetched. A ref may explicitly say unreviewed/unknown, and cannot attest itself.

cases is sorted by case_id, unique across dataset. Each case has exactly:
case_id, family_id, split, origin, authorship_ref, rights_ref, split_review_ref, question, language, product, version, scope, answerability, modality, acceptable_facts, disallowed_claims, requirements.

split is tuning|held_out. origin is synthetic|human_declared. question is exact UTF8 text with at least one non-whitespace character, <=8192 codepoints/32768 UTF8 bytes; whitespace/newlines/technical syntax remain unchanged. language matches [A-Za-z][A-Za-z0-9_-]{0,63} (a declared token, not automatic detection or proof of a standardized language tag). product and version are each null or nonempty UTF8 text<=256 codepoints/1024 UTF8 bytes. Null means unknown, not latest/all versions. modality must be text in v1; visual records require a future separate source/region contract, not fabricated text quality.

scope is exactly corpora, versions, labels. Each is a list of unique lexically sorted nonempty UTF8 strings<=256 codepoints/1024 UTF8 bytes; corpora/versions<=128 entries and labels<=64. Empty lists mean unspecified declared test context, not permission or unrestricted principal authority. These are evaluation metadata, NOT provenance.Grants or an authenticated principal; this parser cannot authorize retrieval or release.

answerability is answerable|unanswerable|unknown. acceptable_facts and disallowed_claims are lists (possibly empty) of exact UTF8 strings with at least one non-whitespace character, <=2000 codepoints/8000 UTF8 bytes, max64 entries each, no exact duplicate within either list. A fact present in both lists refuses. Preserve listed order; the parser does not judge truth or paraphrase equivalence. Answerable requires at least one acceptable fact and one requirement. Unanswerable/unknown require no gold requirements; acceptable/disallowed lists remain declared expectations and may be empty. Unknown is not an evaluated successful abstention case.

## Gold requirements

requirements is sorted by unique requirement_id, max16 per case. Each requirement has exactly requirement_id, grade, alternatives. grade is strict int1..3, a declared relevance grade rather than a measured judgment. alternatives has1..8 elements, each a list of1..8 GoldSpan atoms that must ALL be covered; satisfying ANY complete alternative can satisfy the requirement. Requirements are conjunctive. This declares an evidence structure, not the final metric formula.

GoldSpan has exactly revision_id, extraction_id, block_id, start, end, text_sha256. Revision/extraction IDs are sha256-prefixed64 lowercase hex. block_id is a nonempty exact UTF8 string<=256 codepoints/1024 UTF8 bytes, compatible with the existing opaque Block identity. start/end are strict ints with0<=start<end<=200000. text_sha256 is bare64 lowercase hex of the intended substring UTF8 bytes, consistent with provenance_records._hash. Atoms use half-open Unicode codepoint offsets, NOT UTF8 byte offsets or chunk/representation/row IDs.

Within each alternative, atoms are sorted and unique by (revision_id,extraction_id,block_id,start,end,text_sha256). Alternatives are unique and sorted by their canonical JSON bytes. Refuse conflicting text_sha256 for the SAME (revision_id,extraction_id,block_id,start,end) anywhere in the dataset. Do not merge overlapping intervals, reorder alternatives or infer equivalence at admission. Bound total atom occurrences4096 even if identical atoms recur legitimately in different requirements/cases.

A later actual source adapter must resolve revision/extraction/Block, verify original substring/hash/bounds and bind retrieved Chunk fragments with the existing Registry. Pure parsing cannot establish that the referenced block exists or that text matches a real original; no source-validation label appears here. Block/page/crop visual attribution and current rights remain separate.

## Split integrity and identity

A family_id must occur in exactly one split. For exact question UTF8 bytes (without normalization), all cases sharing that question must occur in the same split, even with different product/version metadata. Same wording across versions may be legitimate inside one split; require distinct case IDs. Same family and question across tuning/held_out refuses. This structural check does not detect paraphrases, leaked source familiarity, prior use in model tuning or a false family declaration. Human semantic leakage review remains mandatory.

Dataset identity: "sha256:"+SHA256(b"slaif-text-evaluation-dataset-v1\n"+canonical_input).hexdigest(). Split identity: the analogous domain b"slaif-text-evaluation-split-v1\n" over canonical JSON with exactly namespace, split_policy_ref and assignments. assignments is the case-ordered list of dicts containing case_id,family_id,split,origin,question_sha256, where question_sha256 is bare SHA256 of exact question UTF8 bytes. This separates split assignment identity from changed gold/facts. A later run must bind BOTH dataset_id and split_id, plus code/snapshot/config/query policy; split identity alone cannot freeze gold data.

Derived counts: case_count, gold_atom_count, synthetic_count, human_declared_count, tuning_count, held_out_count, held_out_human_declared_count. They count admitted declarations only. Empty held-out or all-synthetic datasets remain admissible development DATA with NOT_QUALIFIED markers; never fail open into human-baseline acceptance. No public logging of questions, low-entropy question hashes, refs or original-span hashes.
