## Lexical grammar

This section specifies the scanner obligation; it grants no execution authority. The wire accepts ordinary JSON object/array punctuation and string/INTEGER tokens only. Outside strings the only whitespace bytes are SPACE0x20, HT0x09, LF0x0A and CR0x0D. Other raw controls are invalid. Inside strings unescaped0x00..0x1F is invalid; DEL/non-ASCII cannot produce a valid declared field and may be refused before construction. Escaped controls still cannot pass the final exact field grammars. Raw bytes>0x7F and any BOM refuse before decoding.

A string begins/ends with a quote and recognizes only JSON escape forms: escaped quote, reverse solidus, slash, b/f/n/r/t, or u followed by EXACTLY four hexadecimal digits. An escaped quote does not end the string; braces/brackets inside strings are not structure. EOF inside a string, after a backslash, or before completing four hex digits refuses. Decoded duplicate object keys are rejected, including e.g. plan_id versus a spelling using a Unicode escape for its initial p. No lone surrogate, surrogate pair yielding non-ASCII, or other non-ASCII value may survive final ASCII field validation. Unicode escapes for allowed ASCII values remain admitted within the770raw/128decoded envelope. Scanner counters must not assume UTF16 code units and Python codepoints are interchangeable; conservative early refusal of invalid non-ASCII/surrogate content is allowed without excluding valid ASCII fields.

Integer lexical form is -?(0|[1-9][0-9]*), length<=20bytes INCLUDING minus. No leading plus, leading zero sequence, decimal point, exponent or nonfinite extension. JSON numeric tokens and quoted strings are different: legal ID strings such as true, null, NaN or 1e2 are not bool/null/float literals and must be evaluated by the field grammar. Exact field type/range checks follow; a numeric negative zero has ordinary JSON integer value0 and is subject to that field's range, without string/float/bool coercion. No truthiness-based admission.

Exactly one root object, correctly matched containers, required separators/colons, no trailing comma and no content after the root except allowed whitespace. Malformed token or structural syntax refuses. The general decoder remains strict as a second check; it is not a substitute for the pre-materialization envelope. No JSON object/list graph, arbitrary-length decoded string/int or whole token list may be constructed before the applicable lexical/structural caps. No arbitrary caller hook, object factory, filesystem adapter or type coercion is part of this API.

Required extra vectors: legal external HT/LF/CR/space versus forbidden raw controls; raw controls inside strings; leading-zero/plus/exponent numbers; complete/incomplete Unicode escapes at EOF; unterminated strings/escapes; quoted literal-looking IDs; decoded escaped duplicate root/nested keys.
