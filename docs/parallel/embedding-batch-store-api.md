# Typed embedding batches, version 1

`publish(store, metadata_bytes, vector_bytes)` admits a bounded canonical UTF-8 JSON declaration and normalized NPY vectors, publishes one `vectors` member, and validates a fresh read before returning the content ID. `load(store, id, expected_metadata_bytes)` validates the complete expected declaration before I/O, rereads the store, requires byte equality and validates vectors again. It returns a frozen result with ordered row IDs and a read-only matrix. A failed publication can leave immutable orphan objects; recovery can retry the same content. This is not a multi-store transaction or job completion.

The exact root fields are `schema` (1), `kind` (`embedding-batch-v1`), `dependencies`, `rows`, `vector_container_sha256`, `vector_payload_sha256`, and `codec_policy_fingerprint`. Dependencies contain `space_id`, `inventory_id`, `definition_fingerprint`, `execution_fingerprint`, `tokenizer_sha256`, `representation_policy_fingerprint` (lowercase SHA-256), and `normalization_policy_id` (the accepted normalization policy ID). Rows contain `chunk_id`, `revision_id`, `extraction_id`, `representation_id`, `rendered_sha256`, `source_scope_sha256`, `input_sha256`, and `token_count`. IDs are bounded, row and representation IDs unique, token counts 2–1024, and batches contain 1–128 ordered rows. Hash fields are lowercase SHA-256. Metadata is at most 131072 bytes, sorted compact JSON without duplicate or unknown fields or floats.

The fixed codec policy limits rows to 128, elements and work to 131072, bytes to 530000, header to 512, deadline to 5000 ms, and norm tolerance to 0.0001. Larger corpora require multiple batches. Declared dependencies and row mappings are caller assertions, not proof of source relationships, encoder execution, or current rights. Real encoder jobs, GPU parity, authorization, license, model quality, hardware qualification, independent audit and MVP remain separate gates; synthetic unit vectors prove none of them.
