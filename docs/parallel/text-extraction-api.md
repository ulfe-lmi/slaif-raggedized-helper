# Native text and Markdown extraction candidate

`extract(store, revision_id, policy=None)` reads a verified revision and its original bytes through `OriginalStore.inspect` and `read_original`. It requires processing-approved source metadata and media type `text/plain` or `text/markdown`; the data must decode as strict UTF-8. Failures raise `ExtractionError("extraction refused")` with no input or partial result. Unsupported media, including PDF, are refused. The store remains caller-owned and must be closed by the caller. This is local processing, not authentication, access enforcement, source serving, real model or tokenizer qualification.

`ExtractionPolicy` is frozen; positive strict integer limits can narrow the version 1 ceilings: 2,000,000 original bytes, 1,000,000 decoded Unicode code points, 4,096 blocks, and 200,000 code points per line/block. Invalid policies raise the input-free `ExtractionError("invalid extraction policy")`; `extract` revalidates supplied policy instances. The policy's canonical `definition` includes the adapter version and every limit, and `fingerprint` is the provenance `extraction_id` of that definition. Extraction uses a five-second cooperative monotonic work deadline checked after store operations, decoding and between lines; a blocked filesystem call cannot be forcibly interrupted. `inspect` verifies a stored blob before the adapter's tighter byte check, and the store's own 64 MiB maximum and private POSIX filesystem assumptions apply. No complete-looking result is returned after a detected limit or deadline failure. These limits do not count model tokens.

The immutable `ExtractionResult` contains the verified `Revision`, its canonical provenance `Scope`, a `Dependency` binding revision and policy fingerprint, and a tuple of native provenance `Block` values. Blocks preserve the exact Unicode text and original line endings, including CRLF, blank lines, combining code points and final incomplete lines. Python `str.splitlines(keepends=True)` defines line boundaries, including Unicode line separators; concatenating block texts reproduces the entire decoded original. Empty originals produce an explicit successful result with zero blocks. Block anchors are `line:1`, `line:2`, etc.; order starts at zero. IDs fingerprint the revision, policy, order, anchor, kind and exact text hash. Identical bytes with different revision metadata therefore retain distinct scope and block identity. No geometry is inferred.

For Markdown, ATX headings with up to three leading spaces, bullet or numbered list markers followed by whitespace, and backtick/tilde fenced code are marked `heading`, `list` and `code`. A matching fence closes only with sufficient markers and trailing whitespace; an unclosed fence remains code to EOF. Each line including fence delimiters is retained. Other lines, including paragraphs, table rows and headers, links, HTML, indentation and unsupported syntax, are literal `text`; plain text marks every line `text`. This is a limited classifier, not a CommonMark renderer or table parser, and does not fetch links, execute commands or interpret source instructions. Repeated text is never deduplicated. Structural, token-aware chunking and PDF/vision extraction remain later work.
