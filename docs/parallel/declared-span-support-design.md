## Exact support semantics

For each K take exactly ranking[:K]. For each source key (revision_id,extraction_id,block_id), gather all fragment intervals from those chunks. Sort intervals numerically by (start,end) for that key and union them. Overlap AND adjacency merge: [0,2)+[2,4) covers [0,4); [0,2)+[3,4) leaves a gap. Duplicate or overlapping fragments never earn additive credit. Different block/revision/extraction keys NEVER merge, even if text/hash looks identical. Multiple distinct chunks may jointly cover one atom; do not require a single chunk unless a later separately versioned metric explicitly says so.

A gold atom is geometrically covered iff ONE merged interval for its exact source key contains its complete [start,end). Partial coverage is false. text_sha256 is part of admitted gold identity but is NOT checked against source text by this algebra. That check belongs to the actual structured-text binding/Registry/catalog adapter; hash equality or a caller interval alone is not source truth. A malicious caller can claim an entire block and get declared support; fixed unverified markers make this limitation explicit.

Within an alternative ALL atoms must be covered; within a requirement ANY complete alternative suffices; across case requirements ALL are needed for complete evidence. Preserve admitted requirement order and alternative indexes (zero-based original admitted order). At every K return each requirement's boolean alternative_covered tuple and covered=any(alternative_covered), covered_requirement_ids in admitted requirement order. Each requirement receives credit once, no extra weight for many alternatives/atoms/chunks or repeated spans. Declared grade1..3 is retained in the input identity but NOT a weight in this unweighted coverage fraction.

When requirement_count>0, requirement_fraction = covered requirement count / requirement_count and complete_requirements = all requirements covered. Positive requirements plus empty ranking => fraction0, completeFalse. When requirement_count=0, fraction=None, complete_requirements=None, undefined_reason=NO_GOLD_REQUIREMENTS; covered IDs and requirement rows empty, not vacuous successful abstention. returned_count=min(K,N). Never call an unanswerable/unknown declaration a correct answer from these values.

This is case-level declared evidence support, not MRR/nDCG or a meaningful single-source versus multi-source held-out Recall denominator. Multi-chunk AND/OR support can become true jointly; do not compress ranks or invent an ideal ranking for graded gain. Actual source Recall@20/60/complete multi-source metrics and any meaningful MRR/nDCG mapping require an explicitly bound evaluation run with an independent gold/source/grade unit policy. This helper never emits source_recall, passed, qualified or answer_correct flags.
