Preexisting directory only, no parent or output-root creation. Record creator PID before locks. Verify path links/finalroot inode/owner/mode by bounded safe re-open after lock, before link and after final verification. Identity comparisons across own directory mutations use dev/ino/owner/mode, not frozen ctime/mtime (own temp/link/unlink legitimately changes directory timestamps). No directory enumeration or unrelated paths.

Process-local registry: reserve one of16 operation slots atomically BEFORE any fd open or filesystem mutation; global PID check BEFORE taking inherited locks. Each slot has creator PID and own non-reentrant operation guard. Registry locks protect atomic slot/token state, not an unbounded global I/O critical section. Six descriptor tokens maximum per slot, counting active/transient/definitely-open AND ambiguous-close tombstones: walker parent/child, heldroot, temp, finalread, bounded recheck spare. <=96 potentially open or unknown tokens overall. Reserve token before open; release only after unambiguous close. First ambiguous close aborts dependent work; never retry that numeric descriptor, because it may already be closed/reused. Retain bounded uncertainty until process restart if it cannot be resolved safely. No new op when slot/token capacity exhausted; generic NOT_PUBLISHED/PENDING refusal before opening.

Retained slots contain only creator/root/temp inode+name/definite handles/unknown tokens/state/locks needed for cleanup, NOT Report/payload/result/trace objects. retry_cleanup validates exact int deadline1..30000, same creator process and serialized slot ownership; visits at most16 pending slots once per call. Unknown tokens remain tombstones and consume slot capacity; never report CLEAN when uncertainty remains. Fork child refuses inherited publish/cleanup operations before locking or touching descriptors; no inherited registry reset/cleanup. A newly exec'd process is a fresh owner. No implicit cleanup scans, automatic destructive recovery or final-file rollback. Process crash leftovers need separately authorized operator inspection.

## Publication protocol and states

1. Complete nominal input/path/hash/deadline admission. Reserve slot; securely open root, acquire exclusive directory lock, recheck namespace. All subsequent file operations dirfd-relative. Check existing final BEFORE creating temp: open O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC, then fstat. This prevents FIFO blocking before type check. Require regular current-owner0400/nlink1, exact expected size, stable pre/post signature and linked no-follow entry; stream exact bytes compare with input, at most cap+oneEOF byte. Refuse unsafe/mismatched objects as CONFLICT; never overwrite/delete them. After exact verification, directory fsync and namespace check, latch DURABLE; owned cleanup clean => EXISTING receipt.
2. If final entry is confirmed absent, create a random fixed-prefix temp O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC mode0600; no unbounded name retries. Track fd/name/inode. Require regular current-owner/nlink1 and linked entry. Write all bytes once in <=64KiB bounded chunks using views, handling short writes; fchmod0400 and filefsync; verify size/link/inode/mode. Complete bytes are staged before any visibility under final basename. No report truncation or append.
3. Recheck namespace. Set publication-attempt state BEFORE atomic hardlink(temp,final,dirfds,follow_symlinks=False) no-replace. If final already exists, do NOT replace: verify identical existing by step1 or CONFLICT, clean only ownedtemp. Cooperating dirlock normally serializes this race; still handle EEXIST honestly. Any uncertain link outcome is POSSIBLY_PUBLISHED until verified.
4. Verify final entry points to exact staged inode, regular/current-owner0400; allow nlink2 ONLY while the two recorded temp/final links exist. Unlink ownedtemp only after matching its current no-follow inode; then verify final stable nlink1. Never unlink final, even on failure. Directoryfsync, reopen final with nonblock/nofollow, stream exact size/bytes/EOF with stable fstat/entry signatures and namespace. Latch DURABLE only once all final checks and directoryfsync succeeded. Close all owned handles/lock cleanly, release slot, return PUBLISHED.

Complete written final may remain visible after error. Before any link attempt, NOT_PUBLISHED means no new final from this call and confirmed absence under lock; known incompatible existing object is CONFLICT. After link attempt, interrupted outcome, failed final verification or failed directoryfsync => POSSIBLY_PUBLISHED, not an assurance of absence/durability. Partialtemp is never linked. Crash between link and tempunlink may leave complete nlink2 final+temp; fresh caller refuses unsafe nlink2 instead of auto-deleting unidentified files. Crash after unlink before directoryfsync leaves uncertain durability. Never translate a failed/uncertain call into absent final or roll back a verified final.

After DURABLE is latched, ordinary cleanup/late-deadline error retains publication DURABLE and cleanup PENDING/CLEAN as actually known, raises PublicationError, and never discards durable state. Distinguish publication uncertainty from cleanup uncertainty. If BaseException happens at any stage, retain accurate bounded operation state, attempt safe bounded cleanup, then re-raise same original object; retry_cleanup reports cleanup counts only. Ordinary errors suppress raw exception context. No automatic re-execution of producer/program, no acquisition/closure of borrowed stores/pins/models.
