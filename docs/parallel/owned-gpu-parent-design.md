The next leaf is the low-level parent, not the service mode controller or a user-facing command. It is unused by product routes until later rights/mode/durable transition admission is wired and reviewed. Its existence never authorizes GPU work. It borrows the caller's already protected, admitted model tree and a separate actual operation reservation. The caller retains that tree and reservation through pending parent cleanup. Parent never releases caller's reservation or mistakes it for the child's DeviceLease.

Operation reservation is an actual registered embedding_job_ownership.Lease, current-process assert_owned(), with job_id fingerprint({kind:'gpu-mode-operation-v1',host_id:H,device_uuid:U}). Require this exact key and actual type; a lookalike DTO/boolean/callback is insufficient. A future controller creates this under its trusted configured state root and persists transition intent before parent construction. Parent verifies reservation before launch and before/after each call but cannot infer durable intent, current rights or physical vacancy from it. Those remain caller/controller gates.

Parent admits immutable definitions/inventory/semantic space/profile and exact explicit CPython3.12 runtime before launch. It creates a fresh private code capsule containing ONLY the child wire.CODE_FILES and exact GPU uv.lock, no .git/checkouts/home/credentials. Borrowed artifact root is bound read-only at /artifacts. Trusted package root read-only /packages, selected runtime read-only /python, fixed capsule /app with source /app/src and worker_profiles/gpu/uv.lock, copied child entry /worker.py and same profile /profile.lock. No model download, arbitrary executable/argv/module/factory/remote loader or public test-mode switch.
