## API and boundary

Borrow exact source_admission.OriginalStore and derived_store.Store; do not close, write, publish or mutate them. dataset_bytes is exact bytes admitted afresh by the actual text_evaluation_dataset.admit, never a caller Dataset/Case/GoldSpan DTO. bundle_ids is exact builtin tuple, lexically sorted unique bare64 lowercase hex container IDs, 0..128. deadline_ms strict int1..120000, no bool/subclass. All exposed ID/hash/status fields are exact builtin str, counts/offsets are exact builtin int (not bool), observations/bindings/matching bundle_ids are exact builtin tuples. Ordinary dataclass equality/hash is acceptable; Python hash is not a stable provenance identity. Every ordinary failure becomes GoldBindingError("text evaluation gold binding refused") from None; original non-Exception identity propagates. No private values in default errors/repr/logs. Raising from None suppresses default exception rendering, not trusted-caller access to __context__. No model/tokenizer execution, subprocess, network, downloads, native profile loading, query dispatch or implicit source admission; inherited source validation may run its established extraction validators, not a new backend.

Caller explicitly selects candidate bundles. Source integrity is a private offline DATA operation; a current reader grant is not required just to check owned synthetic/private originals inside an already-authorized local operation. This API does NOT grant authority to use real private data or disclose it. Current withdrawal/version policy, processing permission changes, principal authorization, dataset storage rights and human held-out provenance must be checked separately before exposure/model use. Immutable stored source metadata and fingerprints do not establish those current facts.

## Actual source validation, two observations

Use actual ingestion_store.load(originals, derived, container_id), which calls the real derived store manifest/member integrity checks and ingestion_bundle.validate against verified controlled originals. Do not replace it with a caller Validated bundle, Registry or parsed manifest; do not use private Registry._blocks as a source oracle. Require actual validated bundle.adapter == "structured_text" and refuse every other adapter. The existing structured-text source re-extraction validator, reconstructed dependency/scope, fresh original blob checks and native chunk/coverage/receipt checks remain active. A PDF container might be fully loaded/checked by inherited load before adapter refusal, but it must NEVER receive this source-text binding status. No framework/model/count process is launched by this new adapter. Do not relabel Registry consistency alone as extraction truth.

For each selected bundle, inspect the actual validated revision, dependency, blocks and canonical metadata/members. Match atoms by the exact (revision_id,extraction_id,block_id) triple; block IDs alone are insufficient. Every selected bundle must match at least one gold atom; reject irrelevant extras, rather than silently loading an arbitrary corpus. Every DISTINCT gold atom must find at least one matching selected bundle. For each match require:

- actual block revision/extraction equal the atom and validated bundle revision/dependency;
- block.origin is native and block.kind is not visual (this v1 binds native structured-text gold only; even native-looking PDF blocks and visual transcription/region gold need separate source-text proof);
- strict half-open Unicode CODEPOINT bounds0<=start<end<=len(block.text), not UTF8 offsets;
- bare SHA256(block.text[start:end].encode("utf-8")) equals text_sha256. No normalization, separator/heading addition, overlap merging or alternate interpretation.

A bundle may contain unreferenced blocks/chunks; its full existing validator still validates them. Different chunk policies may yield multiple individually valid bundles for the same original extraction. Allow that when EVERY matching atom passes in each such bundle; record ALL matching bundle IDs, no first/last winner. A selected bundle with the same revision but a different extraction or missing block cannot count as a match. Ambiguous duplicate actual block identities inside one bundle are already rejected by inherited source/Registry validation. Any matching atom mismatch is a refusal, not ignored because another bundle matched it.

First pass computes exact observations and each atom's matching bundle IDs. Then perform a SECOND full load/validation pass in the same deterministic bundle order, enforcing the same aggregate bounds again, rechecking every matched substring and recomputing observations and binding membership. Require exact equality with first-pass observations/membership, no caller DTO/hash-only shortcut. Release per-bundle temporary data before loading the next. Two observations are NOT an atomic global source/policy snapshot or a proof against transient changes/ABA between reads; immutable content identities plus actual checks describe only the observations made. Current rights/withdrawal remains separate. No unknown execution, journal ownership or job repair logic belongs here.

For a dataset with ZERO gold occurrences, bundle_ids must be empty; return explicit NO_GOLD_SOURCE_VALIDATED with empty observations/bindings and counts0, after real parser/deadline/hash/result checks. No store load/close occurs. This is an admitted unanswerable/unknown development dataset, not evidence of a correct abstention or a qualified store. For any positive gold, empty bundles refuse before loads. Closed stores may be unused only in the zero-gold case; never report that as successful source/store validation.

## Output, provenance and privacy

All records are frozen dataclasses with repr=False and tuple collections. No raw block/chunk/question text, source paths or complete dataset bytes are retained in the output. Exact data fields:

BundleObservation: bundle_id, metadata_sha256 (bare hash of actual validated canonical metadata_json), revision_id, extraction_id, block_count (actual len(blocks)), member_bytes (len(metadata_json)+sum(len(data) for name,data in members)). These observed sizes are ints. Bundle IDs are bare container IDs and bind the store's existing manifest/member identity; do not replace them by metadata hashes.

GoldBinding: revision_id, extraction_id, block_id, start, end, text_sha256, bundle_ids (sorted unique IDs of ALL selected matching bundles). One entry per distinct atom, sorted by the full atom tuple above. No copied substring in result.

BoundGold: dataset_id, split_id, dataset_sha256 (bare SHA256 of exact admitted dataset bytes), binding_id, observations:tuple[BundleObservation,...] in selected bundle order, bindings:tuple[GoldBinding,...], case_count, gold_atom_occurrences, distinct_atom_count, source_binding_status. Status is ORIGINALS_REVALIDATED_AT_BIND_TIME for positive gold with both matching passes, or NO_GOLD_SOURCE_VALIDATED for zero gold. It describes source-integrity observations, not execution or human verification. Fixed top-level non-init markers: qualification=NOT_QUALIFIED, authorship_status=DECLARED_UNVERIFIED, rights_status=DECLARED_UNVERIFIED, split_status=STRUCTURAL_ONLY. No method promotes these markers; frozen DTOs can be fabricated by trusted Python code and MUST NOT be accepted by a downstream source/evaluation gate in lieu of fresh input/store validation.
