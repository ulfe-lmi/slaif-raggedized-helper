# Provenance records API (candidate v1)

`provenance_records` is a bounded in-memory validation layer for supplied records. It does not extract text, invoke a model, verify actual execution, authenticate readers, enforce current policy or serve source content. Synthetic inputs and token counts do not qualify an extractor or tokenizer. Original bytes are separately managed by `source_admission.OriginalStore`; use its `inspect` for blob verification before building a catalog. The catalog verifies structural revision identity and approval, not the presence or authenticity of a blob or an authority's approval.

All DTOs are frozen, strict, extra-forbidden Pydantic models with mandatory integer `schema_version=1`; tuple fields must be tuples. Public binding helpers revalidate snapshots, including copies made with Pydantic's unchecked copy/construct interfaces. Direct DTO construction may raise Pydantic `ValidationError`; binding helpers raise input-free `ProvenanceError`. Do not log DTOs or validation input: deliberately retained artifacts contain source text and potentially sensitive identifiers.

`catalog(tuple[Revision, ...])` validates the actual source and revision contracts, the source-revision fingerprint, blob hash binding and processing approval. It returns canonical `Scope` records: document, revision, corpus, optional declared version, sorted ALL-required labels, processing approval and separate redistribution rights. Empty labels mean public classification; missing labels are invalid. Equal bytes do not merge scopes. A metadata change yields a new source revision. Catalog callers must supply their approved revision set, preferably inspected from the store.

`extraction_id(definition)` and `policy_id(definition)` produce distinct versioned `schema.fingerprint` digests over the bounded exact supplied definition. The fingerprint scheme uses sorted compact JSON, ASCII escaping and the `slaif-fingerprint-v1` prefix. Descriptions must capture all relevant inputs; these identifiers are declarations, not execution evidence. `Dependency` binds a revision to an extraction ID and its definition. `Block` binds a stable caller-provided block ID, order, kind, anchor, exact text and SHA-256 over its UTF-8 encoding to that dependency. IDs and order must be unique within the registry (block IDs globally). Native and literal visual transcription are distinct; the latter requires an original page reference and explicit uncertainty, and may include crop and actual supplied geometry. Geometry is optional, finite and ordered; it is never inferred. Interpretation and context are separate `Derived` records, never original blocks.

`Registry(revisions, dependencies, blocks)` validates and snapshots the catalog, dependencies and blocks. `bind_chunk(chunk)` returns the whole revision's `Scope` only after resolving every fragment, checking revision/extraction bindings, exact text and SHA-256, policy fingerprint format and `chunk_id`. `chunk_id(chunk)` hashes every chunk field except the ID itself, including dependencies, policy, text, fragments and counts. Construct a chunk with a temporary ID and replace it with this value before binding. The policy fingerprint identifies a supplied definition; the registry does not resolve policy definitions or qualify policy execution.

A `SourceFragment` copies a nonempty substring of a block using start-inclusive/end-exclusive Unicode code-point offsets, not UTF-8 bytes, graphemes or tokens. Empty source fragments and empty separators are rejected. An explicit `Separator` records inserted text. Fragments are ordered, can repeat an original table header, and must include at least one source fragment. Concatenation must equal the exact claimed chunk text; no normalization occurs. `TokenCount` requires either `available` with a nonnegative bounded integer, or `unavailable` with null, and always carries explicit provenance. It records a caller declaration, not an independent count check or qualification.

`bind_derived(derived)` resolves the target and every original support, unions their labels, and rejects support crossing the target document, revision, corpus or access boundary even when the caller has all labels. Interpretation requires an original page reference and uncertainty; crop is optional. Derived text is not source evidence. This layer does not validate semantic entailment, authenticate references to images, or validate generated content.

`reader_allows(scope, grants, restrictions=None)` is a pure intersection helper. The scope must come from the validated catalog/registry; a standalone caller-created `Scope` is not evidence of authorization. Operator `Grants` must explicitly list corpora and versions and all required labels; absent grants, empty version grants and unknown source versions deny. Optional caller corpus/version restrictions only narrow. This is not authentication, a current-policy or revocation check, nor retrieval admission.

Limits: at most 128 revisions/dependencies, 4096 blocks, 256 fragments/supports per artifact, 200,000 code points per block/chunk/derived text, 16 token counts, 64 labels per source, and bounded metadata fields as declared in the models. This is not the complete 005 objective: jobs/attempts, real extraction, persistence of these records, execution and canonical composition remain future work.
