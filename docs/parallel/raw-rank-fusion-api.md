# Raw rank fusion DATA interface

`fuse(originals, derived, store_root, snapshot_id, query_id, *, dense, lexical, grants, restrictions=None, k=60, deadline_ms=120000)` borrows actual stores and loads the explicitly named catalog twice. It returns frozen `FusionResult` or raises content-free `FusionError`; interrupts propagate. One cooperative deadline spans the operation. It is not preemptive and does not provide atomic current permission.

`Entry(ordinal, partition_id, chunk_id, revision_id, representation_id, rank)` and `Ranking(modality, declared_status, snapshot_id, catalog_id, query_id, entries)` are frozen slots. Entries are exact tuples of at most 60 per modality, with contiguous ranks and no duplicate row or representation. Representation and query IDs are bare lowercase 64-hex; source IDs use `sha256:`. Query identity and caller-declared COMPLETE/UNAVAILABLE statuses are unverified. Both unavailable refuse; one unavailable marks degradation; empty complete is distinct. `k` is 1–60. A supplied ranking is not evidence that every source row was scored or that an earlier cap was absent.

Static trusted-caller `Grants` and optional `Restrictions` are bounded and independently snapshotted before source loading. None grants and unknown source version deny. Every supplied candidate must match the actual catalog and pass `reader_allows` before any contribution, even if a later cap would discard it. Selected hits are independently rechecked. This does not establish current policy or authorize a serving response.

`Hit` contains ordinal, partition_id, chunk_id, revision_id, representation_id, actual scope_bytes and original_chunk_bytes, dense_rank, lexical_rank, score and global rank. Equal-weight RRF uses `1/(60+rank)` per supplied modality, then descending score and chunk/revision/representation ID tie order. `FusionResult` contains snapshot_id, catalog_id, query_id, ranking_origin (`SUPPLIED_UNVERIFIED`), qualification (`NOT_QUALIFIED`), dense_status, lexical_status, degraded, hits, dense_input_rows, lexical_input_rows, unique_candidates, overlap_candidates, returned and global_cap_applied. Counts cover only the supplied bounded lists. The future application must retain the original engine provenance, input caps and eligible/matching counts, and bind both rankings to actual execution for the same request; this interface cannot prove backend availability or readiness.

Before loading the source, fusion captures independent bounded Ranking and Entry values and validates the captured values. Later mutation of caller-owned DTO instances cannot change the admitted operation. This does not establish a trusted query or engine provenance.
