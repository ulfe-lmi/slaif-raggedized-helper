# Local source import and verified original read

`python -m slaif_raggedized_helper.source_cli import --root ROOT --store STORE --manifest MANIFEST` imports a bounded manifest using the explicitly selected operator-approved local root and private store. `python -m slaif_raggedized_helper.source_cli inspect --store STORE --revision sha256:...` verifies and prints the revision and its source metadata as JSON. `--help` describes flags. These commands are local operator tools; neither authenticates an operator nor authorizes source serving. Display URIs are metadata and are never fetched. No original bytes are printed by either command.

The manifest is read from a regular file descriptor with final symlinks refused, nonblocking open, a 256,000 byte cap, and before/after identity, size, mode and change-time checks. Input must be UTF-8 JSON with no duplicate keys, nonfinite constants, invalid Unicode, unknown schema fields or coercion; version 1 admits up to 128 sources. Every source must supply processing approval, rights, corpus and explicit ACL labels (empty means public). The CLI validates the entire manifest and approvals, approved root and store before starting source admission. Operator-supplied approval is metadata, not authentication or legal verification.

Success exits 0 and prints `status: complete` with ordered `revisions` on import or `revision` metadata on inspect. Failures exit 1 and print input-free JSON to stderr with `stage`, `completed_revisions` and `current_document`. On an import failure, completed IDs identify the records confirmed by earlier admissions in this invocation; `current_document: unknown` means the failing document may have left a blob or even a complete revision before the error. Import is per-document, not a batch transaction. Correct the problem and retry: existing objects are reused only after validation. Do not infer that an empty completed list means no object was published. Interruptions and output stream failures can prevent a complete status report; inspect the private store before deciding what to retry. Inspect may create a missing empty store and then fail to find the revision.

`OriginalStore.read_original(revision_id) -> bytes` verifies the revision record, metadata fingerprint and blob binding, then reads a bounded regular blob through the store's no-follow descriptor and validates the returned bytes against the revision's exact size and SHA-256. File metadata is checked before and after each descriptor read, ignoring atime. `inspect` uses the same verification. The returned original is internal data; it is not an ACL check, authentication, revocation, extraction or serving API. Opened stores must be closed with `close()`.

The store requires a private operator-controlled POSIX directory and a local filesystem supporting hard-link atomic publication and directory fsync; it assumes the store and its parent are protected against untrusted local mutation. Source traversal does not follow symlinks and validates descriptor changes and directory bindings. Atomicity is per immutable blob/revision, not across the manifest. Identical blobs can be shared while source revisions retain their independent metadata, rights and ACLs. Source contents, private paths and raw exceptions are omitted from routine CLI errors; explicit inspect output can contain sensitive operator metadata and should be protected accordingly. No network, models, corpus extraction, snapshot or live qualification is provided.
