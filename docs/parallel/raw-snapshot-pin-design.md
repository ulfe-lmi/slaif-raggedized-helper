## Public owners and lifetime

Provide caller-created PinOwner and RetirementOwner captures. Their constructors perform no filesystem acquisition. The caller keeps the capture BEFORE invoking its fallible acquire method, so failed acquisition, interrupted return and cleanup retain the actual owner without mutating an exception. Exact creator PID, one acquisition attempt per capture, nonblocking thread guard and explicit NEW/ACQUIRING/ACTIVE/CLEANUP_PENDING/CLOSED states; no subclass or caller DTO substitutes. A context manager may close on exit but must not acquire during construction. No destructor-based numeric FD close or silent exception swallowing.

PinOwner.acquire_selected_data(originals, derived, store_root, *, deadline_ms=30000) returns frozen PinData(pointer, data), also retained on the owner. pointer/data are the actual source-validated selection observations, not authority. Missing current selection refuses explicitly rather than yielding a usable empty handle. PinOwner.check(*, deadline_ms=30000) freshly validates configured root/namespace/target identity and actual source-backed named directory, comparing its complete detached data with the captured data; it returns the same PinData. PinOwner.close() releases resources and is idempotent after confirmed closure. Calls after closure, fork, during another active method or after failed acquisition refuse appropriately; failed acquisition remains closeable. Exposing snapshot ID/captured DATA is descriptive, never a READY or permission flag.

RetirementOwner.acquire_unselected_data(originals, derived, store_root, snapshot_id, *, deadline_ms=30000) acquires a LIVE guard for one currently unselected, actual source-validated published snapshot. It refuses the current selection even if no reader holds it. Missing target or invalid data refuses. RetirementOwner.check() verifies the still-held namespace/target association, the unchanged current pointer observation and actual source-backed target; close releases the guard. The guard holds its locks until explicit close and cannot be reduced to a boolean that remains valid after release. It performs NO file removal or external action. A later purger must operate inside this actual guard and separately establish its own authority and original/derived retention rules.

No borrowed store is closed. Both captures preserve original non-Exception identity and prefer a cleanup non-Exception over an ordinary error, following existing ownership contracts. Ordinary public errors are content-free. An uncertain os.close is never retried by numeric descriptor; retain the actual pending owner and distinguish CLEANUP_PENDING from confirmed CLOSED. Caller capture and existing pending-owner mechanisms remain reachable on every failure, including hostile BaseException objects that reject attribute assignment. Retry only known safe cleanup in the creator process; do not advertise a pending lock as released. Explicitly disclose Python allocation/asynchronous-interruption windows already present in underlying owner helpers rather than claiming syscall-level atomicity.

## Lock protocol

All calls first perform cheap exact type/path/ID/deadline admission. Reuse bounded normalized absolute UTF8 root <=4096 bytes, private local directory and no-symlink rules. This new interface additionally admits at most64 root path components before opening ancestors; it changes no predecessor bound. Exact existing OriginalStore/derived_store.Store, sha256-prefixed snapshot IDs, deadline exact int1..120000 (bool refused). One original cooperative deadline covers every stage, lock wait, validation and cleanup; nested loaders keep existing inner bounds, with before/after checks, no hard preemption or renewed budget. Reader resources per owner remain bounded by this path and existing snapshot limits; aggregate service concurrency/memory remains unqualified.

Reader acquisition must hold the ACTUAL shared namespace flock on the actual snapshots directory while reading current.json, source-validating that selection, acquiring a SHARED flock on the actual selected snapshot directory and rechecking root/namespace/pointer/target associations. Only then release the namespace flock. Preserve the selected pointer's actual generation/bytes. The returned reader owner retains actual root, namespace and target FDs plus the target shared flock for its lifetime; it must NOT retain a duplicated namespace locking open-file-description that blocks all future activation. If retaining root/namespace descriptors, open new independent descriptions using safe dir_fd operations rather than dup of the locking descriptor. Do not close another operation's borrowed FD or change existing selection/publication cleanup.

This lets a cooperating writer acquire the namespace exclusive flock and select B while a reader still holds A. New selection alone must not redirect or invalidate the reader's explicit snapshot observation. Reader check does not require current pointer still equal A. It does require the configured namespace and A's actual target link/inode remain the captured ones and source-backed data remain valid at observed boundaries. A pathname can still disappear through a noncooperating actor; refuse on detection, do not pretend the advisory lock physically prevented it.

Retirement acquisition takes the ACTUAL exclusive namespace flock, reads/validates current pointer and target, refuses selected target, then takes an EXCLUSIVE flock on that target using a separate actual open description. It retains BOTH exclusive locks through guard lifetime, preventing selection of that target while guarded and conflicting with existing reader pins. Lock order is always namespace then target; no target-to-namespace acquisition. Readers release namespace after acquisition and their close path never needs to acquire it, avoiding a writer/reader deadlock. A failed/timed-out retirement attempt cleans up its namespace lock so normal selection can continue, subject to explicit cleanup uncertainty.

Existing _Operation and _Owner internals may be reused with explicit ownership accounting. A capture must retain an operation before any fallible open, keep original thread/PID guards consistent and release each known descriptor exactly once. In particular a retirement guard can own the operation for its entire lifetime; it must not call the normal _run helper that cleans the operation before returning. Reader owner transfers/acquires its own target resources while namespace protection exists, then finishes the temporary selection operation. No caller callback, factory, scorer, custom loader or arbitrary locking path is accepted.
