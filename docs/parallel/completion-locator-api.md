# Completion locator bridge

`raw_snapshot_completion_locator.encode(program_bytes, execution_result, *, deadline_ms=30000)` returns canonical ASCII locator bytes for the existing program coverage builder. It accepts a canonical source program and exact executor DTOs, bounded to 4096 rows and 128 ordered batches. It checks the `sha256:` prefix on each output reference and emits the bare container ID, preserving order. Errors are content-free `CompletionLocatorError`; non-Exception interruptions propagate. The 1–120000 ms monotonic deadline is cooperative, including checks around parsing, admission and serialization; it cannot preempt the parser. Program bytes are limited to 16 MiB and locator output to 65536 bytes.

This is a private structural conversion. A DTO can be forged: neither its type nor this conversion proves successful embedding, source integrity, rights, journal integrity or model qualification. Unused execution and native metadata, job IDs and reuse flags are neither inspected nor authenticated. Fresh `raw_snapshot_program_coverage.build` must independently reload and verify the actual sources, program, batches and rows before downstream use. Publication, selection, query and current policy are outside this component. The strongest objection is that a locator may be mistaken for proof of embedding; these trust boundaries and the required fresh coverage step are essential.
