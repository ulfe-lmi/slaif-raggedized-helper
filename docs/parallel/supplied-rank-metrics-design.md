aggregate(cases, *, cutoffs=(20,60), deadline_ms=5000)

Validate exact types and collection cardinalities before walking members; validate/encode each bounded ID and charge bytes before retaining derived data. ## Query formulas and explicit denominators

positive_gold is the set of unique gold IDs with grade>0; G its size. For cutoff K, supplied prefix is ranking[:K], returned_at_k=min(K,len(ranking)); K is retained as requested, not silently replaced by returned count. Relevant returned are prefix IDs in positive_gold. Each unit receives credit at most once because rankings are unique.

When G>0:
- recall = relevant_returned/G, including relevant units never retrieved in the denominator.
- reciprocal_rank = 1/r for the first positive-gold unit at supplied rank r<=K, else0. This is per-query reciprocal rank; only aggregate calls its mean MRR.
- gain(grade)=2**grade-1; DCG is math.fsum(gain(gold_grade_or_zero)/log2(r+1)) for r1..returned_at_k. Rank discounts include irrelevant positions; never compress ranks after filtering.
- IDCG uses ALL gold grades>0 sorted descending, first min(K,G), assigned ideal ranks1..min(K,G). It does NOT use returned_at_k to shrink the ideal. nDCG=DCG/IDCG.

Known grades/ranks bound all arithmetic. Use finite floats/math.fsum; refuse material numerical excursions. nDCG within roundoff1e-12 of0/1 may clamp to[0,1]; larger excursions refuse rather than hide malformed math. No arbitrary supplied scores or floating grades.

When G=0 (empty or all-zero gold): recall, reciprocal_rank and nDCG are None with reason UNDEFINED_EMPTY_POSITIVE_GOLD. DCG=IDCG=0; known returned/relevance counts retained. This is neither a perfect score nor proof of a correct unanswerable response. When G>0 but ranking is empty, all three defined metrics are0, not None.

Output records are frozen dataclasses, repr=False (including all nested records), with exactly the following declared data fields plus the four fixed non-init markers on top-level results. All collection fields are exact immutable tuples; count fields are ints, computed scalars are finite floats or the explicit None below. Public class names are QueryResult, AtK, AggregateResult, AggregateAtK and StageResult. No raw input gold/ranking is retained in result fields.

QueryResult: query_id:str, input_fingerprint:str, positive_gold_count:int, ranking_count:int, at_k:tuple[AtK,...].
AtK: k:int, returned_at_k:int, relevant_returned:int, dcg:float, idcg:float, recall:float|None, reciprocal_rank:float|None, ndcg:float|None, undefined_reason:str|None. For G>0 reason=None; for G=0 reason=UNDEFINED_EMPTY_POSITIVE_GOLD. The four markers input_origin, qualification, relevance_unit and formula_version must be caller-unselectable via init=False frozen fields or read-only fixed properties, never constructor parameters. Nested AtK has no marker fields.

## Aggregate means

Validate raw cases and score each under ONE original invocation deadline. Same cutoffs/policy for every case. Return total_queries, defined_queries(G>0), undefined_empty_gold_queries, input_fingerprint, query_results and at_k. At each K, mean recall, MRR and mean nDCG use only the explicitly counted defined queries, with math.fsum/defined_queries. If none are defined, all means are None, never zero/perfect. Retain total/defined/undefined counts for every aggregate. No hidden dropped query. Unique IDs only prevent duplicate query_id within this invocation; different IDs with identical semantic cases and duplicates across invocations are not detected. This primitive does not establish independent samples, held-out separation or prevent cross-call sample inflation.

AggregateResult data fields: total_queries:int, defined_queries:int, undefined_empty_gold_queries:int, input_fingerprint:str, query_results:tuple[QueryResult,...], at_k:tuple[AggregateAtK,...], plus the four fixed markers. query_results preserves case order and its fingerprints use the aggregate invocation's EXACT cutoffs, identical to score_query of that same case/cutoffs. AggregateAtK fields: k:int, mean_recall:float|None, mrr:float|None, mean_ndcg:float|None, defined_queries:int, undefined_empty_gold_queries:int, total_queries:int. Nested aggregate counts equal top-level counts at every K.

## Cap-stage loss

Validate gold and any available stage IDs before computing. If either before or after is None, status=UNAVAILABLE, reason=MISSING_STAGE_IDENTITIES; report each known count, but removed IDs/count and gold loss/recalls/retention are None, not guessed from counts. Do not expose an empty tuple as proof of zero lost identities.

If both are tuples, require set(after)<=set(before); otherwise refuse because this primitive models a removal/cap boundary, not union/expansion. status=AVAILABLE, reason=None. removed_ids=sorted(before-after); gold_removed_ids=sorted(removed intersect positive_gold); removed_count and gold_removed_count explicit. before_count/after_count include irrelevant IDs. If G>0, recall_before=|before intersect positive_gold|/G; recall_after analogous; recall_loss=gold_removed_count/G. If G=0, these recalls/loss are None; gold_removed_count0 is still an observed empty intersection. retained_fraction=after_count/before_count when before_count>0, elseNone. With known empty before/after and positive gold, recall_before=recall_after=loss0 and retained_fractionNone; this says no loss at that stage, not successful retrieval.

StageResult data fields: input_fingerprint:str, status:str, reason:str|None, positive_gold_count:int, before_count:int|None, after_count:int|None, removed_ids:tuple[str,...]|None, gold_removed_ids:tuple[str,...]|None, removed_count:int|None, gold_removed_count:int|None, recall_before:float|None, recall_after:float|None, recall_loss:float|None, retained_fraction:float|None, gold_metrics_status:str, plus the four fixed markers. A known stage has count=len(stage), including zero; an unavailable stage has count=None. If either stage is unavailable, ALL removed/gold-removed fields, recalls, loss and retained_fraction are None, gold_metrics_status=UNAVAILABLE_STAGE_IDENTITIES regardless of G. If both stages are known, removed tuples/counts are observed even for empty gold; gold_metrics_status=DEFINED when G>0 or UNDEFINED_EMPTY_POSITIVE_GOLD when G=0. The overall status/reason is AVAILABLE/None for both known, including G=0. Sorting IDs means Python Unicode code-point lexicographic order, without normalization. Supplied stage IDs do not prove that any engine actually emitted them or that denied rows were excluded. Real cap attribution remains unavailable in current raw engine reports until a separately scoped actual trace adapter exists.

## Fingerprint domains

Each input_fingerprint is exactly "sha256:" followed by64 lowercase hex digits of SHA256(domain_prefix + canonical_JSON_ASCII_bytes). Canonical JSON uses sort_keys=True, ensure_ascii=True, separators=(",",":"), allow_nan=False, no trailing newline. Tuples recursively become JSON arrays with order unchanged; None becomes null. Dictionary key sorting and all required ID/case sorting use Python Unicode code-point order, not locale, UTF8 bytes or normalization. The exact object schemas (literal key names, no other keys) and distinct raw prefixes ending ONE LF are:

- Query: {"query_id":query_id,"gold":gold,"ranking":ranking,"cutoffs":cutoffs}; domain b"slaif-supplied-rank-query-v1\n".
- Aggregate: {"cases":cases,"cutoffs":cutoffs}; domain b"slaif-supplied-rank-aggregate-v1\n". Each case array is [query_id,gold,ranking].
- Stage: {"gold":gold,"before":before,"after":after}; domain b"slaif-supplied-rank-stage-loss-v1\n"; preserve unavailable stages as null and known-empty stages as [].

These domains version this fixed formula/policy. They do not replace downstream code/dataset/split/snapshot/query-policy/actual-execution provenance. IDs, fingerprints and results remain private DATA: hashes are linkable and may be dictionary attacked, not anonymization. repr=False prevents implicit dataclass value rendering only; explicit field access, dataclasses.asdict, equality, hashing or caller serialization can expose/use private values. Standard frozen-dataclass equality/hash semantics are acceptable, but Python hash(result) is not a stable fingerprint and must not be presented as one. No implicit logging or export. Caller must govern explicit access/export; the primitive cannot enforce downstream handling.

## Independent oracle and safe scope

A hand-derived synthetic oracle should cover gold A:3,B:2,C:1, ranking X,B,A,C; correct rank gaps and graded gains at K1/3/5; short ranking A alone at K3 with full ideal; empty/all-zero gold versus no hits; duplicate IDs, bool/float grades, wrong order/types, cutoffs/work/bytes/deadline, original BaseException and privacy. Specifically q1 has gold A3/B2/C1 and ranking X,B,A,C; q2 has the SAME gold and ranking A alone; q3 has empty gold and ranking X. With cutoffs1/3/5, the aggregate must report2 defined of3, macro recall@3=0.5 and MRR@3=0.75, not divide by3. Stage before(A,B,X),after(B,X) loses A, recall2/3->1/3 with loss1/3; C was already absent and cannot be called cap loss. Missing identities yield UNAVAILABLE, whereas known empty stages have observed0 removals.

This computes generic supplied-ID metrics only. A future original-span adapter must define meaningful relevance units, AND/OR alternatives, union/containment and duplicate credit without compressing actual ranks or inventing an ideal. MRR/nDCG may remain unavailable for nondecomposable multi-chunk support, while separate original-span/source/multi-source coverage is computed explicitly. Never rename these numbers to source Recall@20/60 or claim the95% human-held-out target merely from a caller label.
