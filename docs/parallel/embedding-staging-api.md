# Embedding staging

`stage(manifest_bytes, artifact_root, definition, tokenizer_definition, expected_inventory_id, *, parent=None, timeout=120)` is a context manager. It yields the frozen `Staged(path, manifest_bytes, space)` only after actual source admission, copying each manifest-declared file, and a second actual admission of the private copy. The tokenizer definition is rebound to the staged tokenizer for the second admission. Both admissions use the same inventory ID and definition and must produce the same space. No unlisted files are copied. The existing manifest limits apply, including 4 GiB per file and 8 GiB total. Copying checks the bytes, size, and source metadata; this and the two admissions read the declared bytes three times. This API does not deserialize weights.

The timeout must be finite, positive, at most 120 seconds, and is shared across both admissions and the copy; each admission is capped at 30 seconds. The deadline is cooperative and cannot interrupt a blocked filesystem call. Pre-yield errors raise `StagingRefused("staging refused")` without chaining input-bearing errors. Exceptions from the caller's context body propagate. Cleanup errors are reported with a fixed message; when the body or staging already failed, a fixed note is attached to that exception.

The optional parent must be an absolute, normalized path to a directory owned by the current user with no group or other permissions. The default is the system temporary directory, accepted if private and owned or if owned by root/current user with the sticky bit. Parent path components are opened without following symlinks, and the parent descriptor is held during creation, copying, and cleanup. The path is checked against the pinned parent and stage before admission of the copy and again before yielding. The caller must trust the parent ancestry and filesystem against concurrent substitution; these checks do not establish trust in every ancestor or prevent a same-UID or privileged adversary from racing later path use. The context owns a randomly named private directory; directories are 0700 and files 0600 during copying, then directories 0500 and files 0400 during use. Cleanup uses pinned descriptors and removes recorded entries only when their inode identities still match; a changed or nonempty tree produces a cleanup failure instead of deleting an unrelated entry.

Keep the context open through future backend loading. The public `Staged` record is forgeable and is not independent evidence. The verification establishes matching bytes, not publisher identity, licensing, durability, or model qualification. Read-only modes do not make files physically immutable against same-UID or privileged writers.
