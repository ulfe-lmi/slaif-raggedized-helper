# Original-backed raw catalog

`load_catalog(originals, derived, store_root, snapshot_id, *, deadline_ms=120000)` borrows exact `OriginalStore` and `derived_store.Store` instances. The root is a normalized bounded absolute private snapshot root and the ID is an explicit `sha256:` snapshot digest. The positive integer deadline is 1–120000 milliseconds, with booleans refused. Checks are cooperative around existing stages and loops; they do not preempt an executing loader or kernel. Ordinary failures become content-free `CatalogError`; non-`Exception` interruptions propagate. Stores remain caller-owned.

The frozen `Catalog` contains the snapshot ID, exact core and row-map bytes, canonical JSON UTF-8 source revision, dependency and original block byte tuples, frozen rows and `catalog_id`. Source records are sorted by revision ID, `(revision ID, extraction ID)` and block ID respectively; identical duplicate keys deduplicate, conflicting keys refuse. Registry bounds are 128 revisions, 128 dependencies and 4096 blocks. A nonempty catalog binds every original chunk through a freshly constructed original-record Registry. Zero rows return empty record tuples without constructing a Registry for the catalog; missing snapshots refuse.

Each `CatalogRow` has canonical raw declaration JSON bytes, canonical original chunk, source and scope JSON bytes, rendered UTF-8 bytes, the bare 64-hex raw representation ID, 4096 normalized FP32 little-endian vector bytes, and immutable `(text, start, end, derivation)` term tuples. Ordinal, partition row and batch row remain distinct in the declaration. Group vectors are associated by selected-group position, then compared to the actual dense partition row; lexical rows are matched to the same declaration. Original chunk text is evidence; rendered text is retrieval input. Neither is a grant or current authorization.

`catalog_id` is `sha256:` plus SHA-256 of compact sorted-key UTF-8 JSON with `version: 1`, snapshot ID, SHA-256 hex digests of core and row-map bytes, ordered digest arrays of each source record class, and ordered rows. Each row is an array of declaration, chunk, source, scope and rendered byte digests, bare representation ID, vector byte digest, and the term tuples as JSON arrays. This conversion identity does not replace the snapshot or representation identity.

The catalog refuses more than 4096 rows, 128 partitions, groups or bundles, and charges retained nonvector content incrementally against 32 MiB: exact byte lengths of core, row map, snapshot ID, catalog ID, each unique canonical source record, and each row's canonical declaration, chunk, source, scope, rendered bytes, canonical JSON term array and representation ID. Vector payloads are separately bounded to 4096 bytes per row, at most 16 MiB. This deterministic content accounting is not a peak RSS bound; valid predecessor data can exceed the catalog budget and will be refused. Existing loader and per-file limits remain in force. Final return freshly reloads and compares the complete configured snapshot; the caller deadline is rechecked. Private cooperative stores and trusted code are assumed, and the result does not establish future rights or readiness.
