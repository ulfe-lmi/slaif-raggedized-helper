# One-batch CPU reference producer

`cpu_embedding_producer.produce` accepts the same source, bundle, model, native and CPU inputs as `cpu_embedding_plan.build`, followed by an actual `derived_store.Store`, journal root and a required authorization provider. Optional purpose and policies match the plan API. It returns a frozen `Result` with the job ID, output reference, canonical metadata, freshly validated batch, execution record and fingerprint, and a reuse flag. A result or other caller-created object is not an access credential.

The provider is a trusted internal boundary: `provider(canonical_plan_bytes, boundary)` must freshly check the caller's current permission for every row and the purpose and return a lowercase 64-hex policy epoch, or refuse. Boundaries are `before_model`, `before_encode`, `before_publish`, `before_complete`, and, on reuse, `before_reuse`. The epoch must remain the same throughout a call. There is no default provider and no caller-supplied epoch or receipt. This contract does not implement or attest the future principal/current-policy store, rights, licenses, or security; integrating that store remains a gate.

The producer rebuilds the complete source plan and predicted schema-2 execution contract before owning the job. It admits a fresh PENDING job to exactly one attempt, records CLAIMED and RUNNING with the actual owner, then starts the fixed isolated CPU session. It compares the observed execution record and fingerprint to the prediction before source text is encoded. The legacy intended CPU identity remains distinct from the predicted and observed execution identity. It rebuilds the source plan at dispatch and before publication and completion, validates receipts and normalized vectors, publishes and freshly loads the typed output, then records COMPLETE with the actual output reference and metadata digest. COMPLETE reuse starts no model; it revalidates the current plan, reads the integrity-checked manifest, compares all plan-bound metadata, and performs fresh journal and typed-store verification before release.

Only PENDING and valid COMPLETE are accepted. No stale-owner stealing, retry, repair or automatic reclaim is performed. A failure after dispatch may leave UNKNOWN_COMPLETION; a failure after publication can leave an immutable orphan. An exception from an atomic journal update can mean that the update committed, so the journal is reread and a committed COMPLETE is never replaced with a failure. No exactly-once inference is claimed. When session cleanup is pending, the content-free exception retains an owner whose `close()` must be retried; the journal lease remains held until the child and associated resources are drained. Interrupts propagate with a cleanup owner when needed.

This is a CPU software reference, not the required qualified exclusive GPU bulk embedding path. The fake-provider composition tests do not establish neural behavior, model parity, hardware performance, actual rights or licensing, ICA, full MVP or production readiness. Whole objective 007 remains partial.
