# Literal PDF structure classifier

`pdf-literal-structure-v2` classifies an immutable tuple of `Line` values without I/O. It returns one kind per input and preserves original text. It accepts at most 4096 lines, 500000 total characters and 200000 characters per line, pages 1–32 and finite ordered bounding boxes. Invalid input or a cooperative two-second budget exhaustion raises an input-free `StructureError`.

Only single logical lines are considered. Lists require a literal bullet or numbered marker. Tables require a literal multi-column header, a following hyphen rule, and at least two same-page rows with matching column starts, or starts at most one character from the header when at least two consecutive rows have identical signatures (or matching pipe column count). The rule is retained as a table row. Incomplete, multiline and unsupported material remains text. These limited literal heuristics cannot solve arbitrary PDF layout; integration of this helper does not establish visual fidelity or MVP acceptance.

Pipe tables require the rule to have exactly the header's number of pipe-separated cells, each containing hyphens and optional spaces. Space tables require a hyphen-and-space rule spanning the header's full trimmed width. Space columns begin at non-whitespace runs after at least two ASCII spaces; rows must share identical starts; each may differ from the header by at most one character. A table requires two data rows. Logical lines containing embedded newlines are unsupported and remain text. These rules do not qualify PDF fidelity.
