# Private raw dense DATA search

`search(originals, derived, store_root, snapshot_id, query_payload, *, query_space_id, query_definition_fingerprint, query_policy_id, query_execution_fingerprint, grants, restrictions=None, k=60, partition_cap=60, deadline_ms=120000)` borrows actual stores and loads the explicitly named source-backed catalog before and after scoring. It refuses the whole request with `DenseSearchError` on invalid input, source changes, deadline or scoring failure. The deadline is cooperative, not hard preemption.

The query is exactly 4096 bytes of finite normalized 1024-dimensional little-endian float32 (norm tolerance 1e-4). Space, policy and execution are bare lowercase 64-hex strings; definition is `sha256:` plus 64 hex digits. They must equal the corresponding declared core embedding fields, including the exact query execution domain. They are supplied metadata, not evidence of actual model origin, hardware, precision or qualified runtime. Results always label query origin `SUPPLIED_UNVERIFIED` and qualification `NOT_QUALIFIED`. NumPy 2.5.4 is required. This DATA function creates no model permission or Ready status.

Grants and restrictions are static trusted-caller data, not current principal policy. Exact existing Grants/Restrictions records are bounded before copying: schema 1, known fields, tuples up to 128 strings, at most 65536 combined codepoints and 262144 UTF-8 canonical bytes for the combined pair, including nulls and delimiters. None grants and source version None deny access. The actual source scope and `reader_allows` select rows before any matrix scoring. Future serving must bind current policy and revocation and a trusted resident query encoder, full execution record and qualified precision.

`DenseResult` is frozen: snapshot and catalog IDs, query payload SHA256, origin and qualification, `hits`, `allowed_partition_counts`, eligible, selected and returned totals, and `partition_cap_applied` and `global_cap_applied`. Each hit has global source ordinal, partition, chunk, revision, bare raw representation ID, canonical scope and original chunk bytes, rank and finite score. Original evidence is not rendered replacement text. Counts disclose only allowed partitions. Eligible counts rows after authorization, selected counts after each partition cap, and returned counts after global k. Ranking is descending float32 dot score, then chunk ID, revision ID and raw representation ID; ranks are global after merge. Both caps are exact integers 1–60. No allowed rows produces a complete empty result after all validation; missing or changed sources refuse.

The existing catalog limits remain: 4096 rows, 128 partitions, 16 MiB vectors and 32 MiB nonvector catalog data, with at most 4194304 vector elements scored. There is no 20k-scale claim. Snapshot and request pinning, retention, current rights, license audit, evaluation, deployment and model qualification remain external gates; the final load provides no atomic guarantee against later change.
