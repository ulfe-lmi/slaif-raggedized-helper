# Private snapshot lifetime coordination

Create a `PinOwner` before calling `acquire_selected_data`. Retain it through all use and close it explicitly. The returned frozen `PinData` contains the observed pointer and source-validated data; it is descriptive, not authorization or readiness. `check` reloads the named source-backed data and verifies the configured root, namespace and target while permitting the current selection to have changed. Original and derived stores are borrowed and must remain available; they are not closed by the owner.

A reader acquires namespace shared then target shared, and releases the namespace lock before returning while retaining independently opened root and namespace descriptors and the target lock. A `RetirementOwner` acquires namespace exclusive then target exclusive for an unselected snapshot and retains both through `close`; `check` revalidates the pointer and source-backed target. A cooperating selection writer waits for that live guard. The reader close does not acquire the namespace lock. Neither owner deletes anything; a future purger must act under the guard and separately establish authority and retention rules for snapshot, original and derived artifacts.

Each capture is creator-process only, one acquisition attempt, and refuses concurrent methods. Close is idempotent only after confirmed closure. An uncertain descriptor close remains `CLEANUP_PENDING`, is never retried by numeric descriptor, and does not claim the lock was released. No destructor performs cleanup. Python allocation and asynchronous interruption windows in underlying owner helpers are not syscall-level atomicity. Deadlines are cooperative, not preemptive; nested source loaders retain their own bounds.

These advisory local filesystem locks coordinate participating operations only; they do not prevent arbitrary unlink or establish cross-host filesystem qualification. This interface does not implement garbage collection, retention policy, current principal authorization, revocation, dispatch/delivery rechecks, serving readiness, or deployment qualification. Those are separate gates.
