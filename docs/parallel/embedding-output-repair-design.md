# Explicit published-output repair v1

Status: FINAL — Root authored D0 software design; no activation or live resource authority.
Provenance: H full-MVP development mandate; A ARCHITECTURE 8.3–8.4; I finite recovery inventory SPIKE-007-RECOVERY-BOUNDARY-A draft/report 3c2919af2fb2da5463aa4b82f7f41bc66789e7fe52e5e877d8b481d2e750e08f, target 99249e7acf45309a641d481f4585227c22ed7775; E publication precedes journal COMPLETE, while current restart refuses RUNNING. DHA NONE.

## Purpose and boundary

Implement one explicit trusted-local API on the existing owned embedding journal to repair a stale RUNNING data-materialization state using a caller-supplied immutable batch reference. This fulfills the narrow ARCH8.4 existing-matching-output case without automatic discovery, retry, neural dispatch, or terminal-state reopening. The ordinary producer/executor path remains unchanged; operator/controller integration is a separate order.

Data integrity and materialization completion are distinct from evidence of neural execution, accounting, authorization provenance of the interrupted run, and physical worker/GPU drain. Successful repair establishes only that the complete declared batch exists and freshly validates under current source/configuration/policy checks. It does not establish old attempt billing or physical vacancy. No caller may infer model readiness or permission for a new dispatch from this repair result.

Matching metadata is necessary, insufficient by itself: trusted current-plan validation is also mandatory. An untrusted document, remote request, old PID, timestamp, or supplied epoch cannot authorize this operation. This API is a local internal primitive for an eventual admitted operator/controller; it is not an HTTP endpoint or current-principal policy implementation.

## API and ownership

Add `handle.repair_running_output(metadata_bytes, container_id, expected_revision, expected_state_bytes, *, validate_current, deadline_ms=5000)` to the handle returned by `Journal(root).own(plan_bytes)`. Do not add a second lease manager, subclassable pseudo-handle or filesystem scanner. The caller owns the live handle and borrowed exact `derived_store.Store`; pass `store` as an explicit keyword. This operation acquires no additional persistent resources and neither closes nor releases those borrowed objects.

`expected_revision` is the exact bare64 current journal revision. `expected_state_bytes` is the canonical bounded serialized `JobState` observed by the caller, including old owner, attempt, timestamp and job identity. Capture exact builtin bytes/str/int arguments before callbacks. Reject malformed, oversized, noncanonical, subclass or ambiguous inputs before mutation. Container is bare64; metadata uses the unchanged batch contract <=131072 bytes. Strict deadline int1..120000ms; no bool. Retain existing journal/event/batch/resource caps. No bound increase or format/schema change.

Return a bounded immutable `OutputRepairResult` with verified typed output, new revision, old attempt_id/owner_id, current repair owner_id, current epoch and observation_ms; fixed labels `materialization=REPAIRED_VALID_OUTPUT`, `execution_origin=SUPPLIED_UNVERIFIED`, `accounting=UNKNOWN`, `physical_drain=UNKNOWN`, `qualification=NOT_QUALIFIED`. Result observations are not fresh authority after return. No raw plan/text/paths, billing amounts, fabricated request IDs or token counts.

The existing lease must pass its real PID/inode/live-owner checks throughout. The prior RUNNING owner must differ from the current lease owner: this is explicit stale-owner repair; an active original attempt uses ordinary completion. A live old journal lease prevents new acquisition. Released flock after parent death is not proof that a model child drained. This operation never launches a replacement worker or releases a device reservation.

## Exact admission and sequence

1. Capture inputs and start one monotonic cooperative deadline before reads/callbacks. Assert current owned handle and read/validate the full journal. Revision must equal expected_revision; canonical final state must exactly equal expected_state_bytes. Require RUNNING, a nonempty existing attempt/old owner, current job identity, no existing terminal attempt/output, and old owner != current lease owner. Any other state refuses without writing: PENDING, CLAIMED, RETRYABLE_FAILED, UNKNOWN_COMPLETION, REJECTED, FAILED, CANCELLED and COMPLETE. No state transitions added to job_records.
2. Call trusted `validate_current(canonical_plan_bytes, "before_repair_validation")`. It MUST freshly validate the original sources, exact representation/configuration and current rights for that whole plan and return one exact builtin bare64 epoch. It must not rely only on matching persisted hashes. Synthetic proof may use a clearly labeled fake provider; that is not current-policy or real-source qualification. Callback receives immutable captured canonical bytes. Exceptions/refusals stop before commit.
3. Through the actual typed batch store validate the explicit container and full expected metadata, vector checksum/shape/normalization and existing plan-binding comparisons for dependencies, every ordered row and codec policy. Do not infer output from an old job label, altered metadata, partial file or a caller-created ValidatedBatch. No whole-store or validator success substitution.
4. Before commit call `validate_current(canonical_plan_bytes, "before_repair_commit")` again. Require the same exact epoch; reassert live ownership and deadline, re-read exact revision/state, and freshly revalidate the actual typed output. Provider may be fallible or change state/store; stale revision, changed epoch, changed metadata or corrupt/missing object refuses. Callback execution is cooperative, not hard-preempted; external proof caps are separate.
5. Append exactly one normal RUNNING -> COMPLETE transition through existing typed transition validation and atomic revision-CAS journal commit. Preserve all previous events and old attempt identity. New terminal state owner_id is null, output freshly verified, updated_ms is wall-clock observation >= prior updated_ms. Terminal Attempt outcome is COMPLETE **for data materialization**, same existing job/attempt; started_ms is that attempt's original CLAIMED timestamp (locate unique matching history), ended_ms is repair observation. request_id/input_tokens/output_tokens remain null; diagnostic_code is exactly `RECOVERED_VALID_OUTPUT`. Observation time is not measured neural completion time. The diagnostic distinguishes this from observed producer completion. Old owner remains visible in immutable prior events; current repair owner appears in returned result, not a fabricated invocation field.
6. Validate freshly committed state/output before success. A failure after replace/fsync can leave COMPLETE committed. Propagate original exception; do not append FAILED, overwrite history or retry blindly. The caller can re-read and use normal verified_output to reconcile. A second repair call on COMPLETE refuses; ordinary verified reuse is the idempotent post-repair operation.

Use existing `_output`, transition and `_commit` semantics. Public `append` remains a trusted low-level API, not an authorization service. Do not broaden its transitions or add bypass flags. A narrowly factored private append helper is allowed only if ordinary append behavior stays byte/contract equivalent. No old RUNNING terminal append possibility becomes implicit recovery permission.

## Error and cleanup behavior

Ordinary exceptions produce an input-free JournalError without exposing callback or source data. Preserve original non-Exception BaseException identity, including KeyboardInterrupt/SystemExit and hostile formatting. Do not stringify arbitrary exceptions. Keep any known cleanup owner discoverable; never consume/retry unknown numeric closes or mutate borrowed leases/stores. Existing context cleanup and postcommit reconciliation rules remain in force. No destructor, background retry, hidden thread or persistent cache.

## Proof-sized acceptance

Use seeded synthetic typed batches and actual on-disk Journal/Store/ownership/CAS; no model, framework worker or native tokenizer is needed.

- Positive: actual old lease writes PENDING/CLAIMED/RUNNING and publishes a one-row typed batch, closes; fresh creator owns the same job, repairs explicit ref, observes exactly one COMPLETE event with same attempt, diagnostic and honest unknown labels, and reloads verified output. Full previous event bytes preserved; second repair refuses while verified_output succeeds.
- Distinct process: a controlled child writes RUNNING and publishes, reports the explicit reference, then remains holding the real lease. Repair acquisition refuses while live; terminate only that owned synthetic child, reacquire and repair. This proves lease exclusion/data repair only, never physical GPU drain. No orphan scanning or actual model child.
- Refuse non-RUNNING states, same active owner, stale revision/expected state/attempt/owner, mismatched dependencies/rows/codec, valid different-plan batch, missing/corrupt objects, epoch change/refusal, expired deadline, closed/forked/replaced lease. Preserve original KeyboardInterrupt identity before mutation and after a real successful commit. No mutation on precommit refusal, including changed epoch/source-validation callback.
- Causal: in one owned temporary source copy omit only the existing complete-plan binding comparison shared by repair's actual typed validation. Genuine different-plan valid batch: original refuses unchanged RUNNING, control admits wrong batch as COMPLETE, restored original refuses, healthy original batch repairs. Keep actual store, vector/hash validation, callbacks, journal transition/CAS and real lease active. Pin exact predicate/source hashes and actual assertions; no replacing repair or load with fake success.
- New unit module runs ordinary unit layout with PYTHONPATH=assigned-src only, no tests/integration path. Integration proof collects in the complete tests/integration suite; no import-time sys.path pollution or duplicate-basename fixture import. Existing focused journal unit regression validates unchanged low-level semantics; full current canonical CI remains a later integration gate.

The order grants one tiny positive, one process-lease case, one causal case and at most six further separately bounded actual-store negative cases. Each case process CPU30/AS1GiB/wall120, five thread counts1, no bytecode, private0700 /tmp ancestry. Cheap parser/unit checks may be grouped within the same caps; no old model/producer suites. Record exact fixture/source/driver/command caps before invocation. Preserve every failed attempt. A failed/extra/changed-cost actual case needs a revised Root plan before rerun. No new network/install/GPU/model/service/private corpus authority.

## Remaining gaps

Explicit locator only: automatic durable orphan discovery/index and original invocation/epoch receipt persistence remain unimplemented. Terminal UNKNOWN/FAILED/CANCELLED cannot be reopened. Actual current-principal/source-policy provider, operator/controller integration, physical resource recovery, retry policy, exactly-once semantics, real model/hardware and full MVP qualification remain separate gates. This primitive is not a crash-recovery completeness claim.
