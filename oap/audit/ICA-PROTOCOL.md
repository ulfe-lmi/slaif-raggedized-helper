# Independent Closure Audit protocol

Audit is a scoped reviewer role with no implementation, merge or deployment authority. Start
from full human PLAN/UPDATE/ARCHITECTURE and current exact merged revision, not progress claims.
Treat orders, reports, README and CI as evidence leads to verify. Record auditor/model/context
provenance and independence limits; the scaffold author's second pass is self-review, not ICA.

For every A01–A40 and any source requirement missing from this index, identify enforcing code,
actual connected runtime path, meaningful positive/negative tests, actual-model/hardware proof
where needed, remaining limitations and exact evidence revision. Classify IMPLEMENTED, PARTIAL,
ABSENT or UNPROVEN. Check unwired adapters, stubs, synthetic-only benchmarks, unsupported licenses,
silent ACL/version/precision/truncation errors, deployment-script gaps and exaggerated claims.
Inspect concrete user/operator journeys. A good test name alone does not prove behavior.

Report actionable gaps with H/A/E/I/C provenance and independent acceptance evidence. Strategy
may order remediation but cannot change historical audit findings. Reaudit relevant changes and
the whole target scope after closure remediation; completing the remediation list is insufficient
if it missed requirements. Apply human DHA/target gate separately. No product % from PR counts.
